# BLOCK RALLY（仮題）仕様書 v0.1

ブラウザ用ブロック崩し。1人／協力／対戦の3モードを持ち、**上下入力とショットを組み合わせた「技」**（スマッシュ・ボレー）で、左右移動だけの従来のブロック崩しから踏み出すことを狙う。

- 仮題は `BLOCK RALLY`。既存の名作を思わせる名前・絵柄は使わない（→ Notion「気をつけていること」）。正式名は実装着手前に確定する。
- 土台は INVADER ASSAULT と同じ構成を踏襲し、**リポジトリは新規に分ける**（公開URLも別になる）。共通部品は移植する。

## 1. 技術方針（INVADER ASSAULT からの引き継ぎ）

| 要素 | 採用 | 備考 |
| --- | --- | --- |

| 描画 | Canvas 2D ＋ 固定タイムステップ 60Hz | ロジックを描画とReactから分離 |
| 論理座標 | 480 × 720（縦持ち前提） | 既存と同じ。実画面へはスケール |
| 素材 | ドット絵＝コード内の文字列、効果音・BGM＝WebAudio合成 | 外部ファイルゼロ |

| 公開 | 静的書き出し＋GitHub Pages（GitHub Actions） | `basePath` はリポジトリ名から自動決定、`.nojekyll` を置く |

`lib/shared/keyboard.ts`（文字入力欄の判定）、`components/shared/TouchPad.tsx`、`lib/game/audio.ts` / `rng.ts`、`lib/versus/net/*`（protocol / host / client / room / socket / loopback / simulate）。

エンジン・入力・音声の可変インスタンスはモジュールスコープの単一インスタンスとして持つ（React Compiler の制約回避）。

## 2. 操作

### 2.1 入力モデル

8方向スティック（またはキーボード）＋ショット＋ポーズ。INVADER と同じキー割り当てを踏襲する。

| 操作 | キーボード | スマホ |
| --- | --- | --- |
| 移動・技の方向指定 | 矢印キー / WASD | 画面下半分のバーチャルスティック |
| ショット（技のトリガー） | SPACE / Z | ショットボタン |
| ポーズ | ESC / P | 画面上のボタン |

- ショットは**押した瞬間だけ**反応する（押しっぱなしで技が連続発動しない）。
- 操作キーは `isTypingTarget()` を通し、**部屋コードの入力欄では横取りしない**。

### 2.2 パドルの可動範囲（モードで変える）

| モード | 可動 | 理由 |
| --- | --- | --- |
| 1人 | 左右のみ | ブロック崩しらしさを保つ |
| 協力 | 左右のみ | 2人の位置取りが読みやすい |
| 対戦 | 自陣内を8方向自由移動 | 前に出て叩く／引いて守るの駆け引きを作る |

対戦の自陣は上下 160px の帯。前に出るほど強く打てるが、抜かれたときに戻れない——というトレードオフを距離で表現する。

## 3. 技（本作の中核）

### 3.1 2種類

| 技 | 入力 | 効果 |
| --- | --- | --- |
| **スマッシュ** | 上 ＋ ショット | 反射速度 ×1.55（上限 700px/s）。反射角を垂直寄り（法線から±20°以内）に矯正。発動後 8フレームは**貫通**（ブロックを壊しても跳ね返らず直進）。 |
| **ボレー（ロブ）** | 下 ＋ ショット | 反射速度 ×0.85。発動から 0.9秒間「ロブ状態」。ロブ中はボールに重力 620px/s² が掛かって山なりに飛び、**ブロックとの当たり判定を無効化してブロックを飛び越える**。壁・パドル・デッドラインの判定は有効。 |

- ロブは着地（＝ロブ時間終了 or パドル／デッドライン接触）で解除。解除の瞬間から通常の等速直線に戻る。
- ロブ中のボールは描画で明確に区別する（軌跡の色・残像）。飛び越えているのか通り抜けているのかが見て分かることを必須要件とする。
- 使いどころ：**1人モード**では硬いブロックの列を越えて奥／上段に届かせる。**対戦モード**では中央のブロック帯を飛び越えて相手コートへ直接落とす主力の攻め手。

### 3.2 成立条件（難易度で切り替える）

| 難易度 | 方式 | 判定窓 | 失敗時 |
| --- | --- | --- | --- |
| やさしい | 溜め方式 | なし（接触前に入力してあれば必ず成立） | ペナルティなし |
| ふつう | ジャストミート | 接触フレーム ±5F（≒±83ms） | 硬直 0.35秒 |
| むずかしい | ジャストミート | ±4F | 硬直 0.35秒 |
| エキスパート | ジャストミート | ±3F | 硬直 0.35秒 |

- 先行入力はボール接触の **12フレーム前**まで受け付ける。それより早い入力は「空振り」として扱う。
- 硬直中は技が出せない（通常の反射になる）。移動は可能。
- 溜め方式では、方向を入れたままにしておけば毎回成立する。読み合いはゲージ管理で作る。

### 3.3 技ゲージ

INVADER の射撃エネルギー制を踏襲する（押しっぱなしで撃ち続けられない仕組みを、技の乱発防止に転用）。

| 項目 | 値 |
| --- | --- |
| ゲージ上限 | 100 |
| スマッシュ消費 | 40 |
| ボレー消費 | 35 |
| 回復 | 22 / 秒 |
| 空振り（失敗）消費 | 12 |

強化アイテムは**倍率式・重ねがけ不可**（上限が伸びすぎないようにする）。

## 4. モード別仕様

### 4.1 1人モード

標準的なブロック崩し＋技。

| 項目 | 値 |
| --- | --- |
| フィールド | 480 × 720、プレイ領域 y = 46〜706 |
| ブロック | 10列 × 8行、1個 44 × 24（左余白 20） |
| ブロック配置 | y = 96〜336 |
| パドル | y = 660、幅 88 × 高さ 14 |
| ボール | 半径 6、初速 300px/s、最大 560px/s |
| ライフ | 3 |

- **ブロック種**：通常（1発）／硬質（3発・スマッシュ貫通の対象）／不壊（技で越える対象）／爆発（周囲を巻き込む）／移動（横に往復）。
- **ステージ**：20面。配置パターンで「技を使わないと崩しにくい形」を意図的に混ぜる（不壊ブロックで下段を塞ぎ、ボレー必須にするなど）。
- **反射**：パドルの当たった位置で角度が変わる（中央＝垂直、端＝±60°）。パドルの移動速度をボールの水平成分に 25% 加算する。
- **スコア**：連続破壊コンボ倍率、ノーミスボーナス、ステージ別ハイスコアを保存。
- 難易度4段階、オートで技を出す補助（やさしい時のみ）、効果音・BGM音量、進行状況リセットをオプションに置く。

### 4.2 協力モード（2人）

フィールドは1人モードと同じ。パドルが2枚、下辺を左右に動く。

- パドル同士は**すり抜ける**（押し合いによるストレスを避ける）。
- **ライフは共有**（3）。どちらの側で落としても共有ライフが減る。
- **連携チェイン**：一方が**ボレーで打ち上げ**、その球をもう一方が**スマッシュで叩く**と連携成立。チェイン数に応じてスコア倍率が上がる（×1.2 / ×1.5 / ×2.0、上限 ×3.0）。落球でリセット。
  - これが協力モードの主目的。「2人で同じことをする」ではなく「**役割を分けて繋ぐ**」形にする。
- 技ゲージは各自独立。
- 相手（＝味方）の技ゲージが常に見える HUD を持つ。
- 対戦相手の構成：**1台2人（同じキーボード／画面下部にパッド2つ）** と **通信2台**。

### 4.3 対戦モード（上下分割）

上下対称のフィールドで、エアホッケーのように打ち合う。中央にブロック帯があるのが本作の特徴。

| 項目 | 値 |
| --- | --- |
| フィールド | 480 × 720 |
| 上デッドライン | y = 40 |
| 上プレイヤーの自陣 | y = 56〜216 |
| 中立ブロック帯 | y = 300〜420（10列 × 5行） |
| 下プレイヤーの自陣 | y = 504〜664 |
| 下デッドライン | y = 680 |
| ボール | 1個。得点でリセット |

- **得点**：相手のデッドラインにボールを通すと 1点。**3点先取**、または **90秒**で時間切れ。
- **時間切れの判定順**：得点 → 中立ブロック撃破数 → アイテム取得数（引き分けを出しにくくする）。
- **OVERDRIVE**：残り 20秒でボール速度 +15%、得点が 2点に。決着を促す。
- **中立ブロック帯**：ボールが通せんぼされるので、素直に打つと自陣側から崩すことになる。**ボレーで飛び越えるのが最短の攻め手**であり、スマッシュの貫通で穴をこじ開けるのがもう一つの手。ここが読み合いの中心になる。
- **アイテムの奪い合い**：中立ブロックを壊すと、壊した側の陣地へアイテムが落ちる。色で持ち主を示し、拾えるのは持ち主だけ（INVADER の「共通の獲物」の踏襲）。
- **アイテム（8種）**：パドル拡張／技ゲージ回復／ゲージ上限強化（倍率式・重ねがけ不可）／スマッシュ強化／ロブ延長／シールド（1回だけ失点を防ぐ）／相手パドル縮小／ボール減速。持続するものは 16秒の時間制限付き。
- **対戦相手の構成**：CPU（4段階）／1台2人（同じキーボード）／通信2台。

## 5. 通信仕様

### 5.1 基本

INVADER ASSAULT と同じ**サーバー権威＋クライアント予測＋巻き戻し補正**。JavaScript では端末間で計算結果が一致しないため、決定論的ロックステップは採用しない。

| 項目 | 値 |
| --- | --- |
| サーバーの進行 | 60Hz 固定ティック（進行役の端末のブラウザ内で動く） |
| 状態の配信 | 20Hz |
| 入力の冗長送信 | 直近3フレーム分を相乗り |
| 予測するもの | **自分のパドル位置のみ** |
| 予測しないもの | 得点・ブロック破壊・アイテム取得・勝敗（サーバーの結果のみ） |

接続方式は3つを同じ形で扱う：直接つなぐ（P2P / WebRTC）／サーバー経由（WebSocket、静的配信では非表示）／同じ端末の別タブ（BroadcastChannel、自動テスト用）。

### 5.2 ボールの扱い（本作固有の要件）

INVADER では相手・敵・弾を「100ms 過去を補間」して滑らかに見せていた。**ボールにこれをそのまま使ってはいけない。** 打ち返す対象が 100ms 遅れて見えると、タイミング技が成立しなくなる。

- ボールは**サーバー状態＋等速外挿**で現在時刻に進めて描画する（ロブ中は重力込みで外挿）。
- 相手パドル・アイテム・破壊エフェクトは従来通り補間で滑らかに見せてよい。
- 外挿とサーバー状態のズレは、しきい値以下なら 1フレームあたり最大 4px の緩やかな補正で寄せる（瞬間移動させない）。

### 5.3 技のラグ補償

タイミング判定をサーバーの受信時刻で行うと、参加側だけが片道遅延分不利になる。

- クライアントは技入力に**押したティック番号**を載せて送る。
- サーバーはそのティックまで巻き戻してボールとパドルの位置関係を再計算し、成立／不成立を判定する（lag compensation）。
- クライアントは押した瞬間に**演出だけ**先行させ、成立の可否はサーバー結果で確定する。演出と結果が食い違った場合は、演出を打ち消してサーバーの結果に合わせる。
- 許容する巻き戻し量は最大 12ティック（200ms）。それを超える申告は現在ティックで判定する。

### 5.4 画面の反転（最重要の落とし穴）

どちらの画面でも自分が下側に見えるよう、参加側は座標を 180度 回して描画する。

> **回した分だけ入力も回してサーバーへ渡す。** 描画の反転処理と入力の反転処理は、必ず**同じファイルに隣り合わせで**置く。片方だけ直すと再発する。

本作では技の方向がそのまま意味を持つため、被害が INVADER より大きい：反転を忘れると、参加側は「上＝スマッシュ」を押したのに**ボレーが出る**。テスト項目に明記する（§7）。

### 5.5 その他の既知の落とし穴（対策込み）

| 落とし穴 | 対策 |
| --- | --- |
| 試合開始前の入力がキューに溜まる | 開始前は送らない。**かつ**サーバー側も試合開始時にキューを捨てる（両方やる） |
| 巻き戻し用の未確定入力が参照のまま | 履歴に積む瞬間に**複製**する |
| 古いスナップショットの適用 | ティック番号で比較して古いものは無視 |
| 順序が入れ替わった入力 | 捨てずに並べ直す |
| 入室・準備完了・勝敗通知の欠落 | 定期的な再送＋スナップショットに結果を載せる |

## 6. 画面遷移

```
タイトル
├── 1人モード → ステージ選択 → ゲーム → リザルト
├── 協力モード → 相手選択（1台2人／通信2台）→ ゲーム → リザルト
├── 対戦モード → 相手選択（CPU／1台2人／通信2台）→ ゲーム → リザルト
└── オプション
```

通信を選んだ場合：接続方式の選択 → 部屋を作る（6文字の部屋コード表示）／部屋コードで参加 → 双方「準備完了」 → カウントダウン → 試合開始。参加リンクの共有にも対応する。

HUD：スコア・ライフ（対戦は耐久と得点）・技ゲージ・残り時間・コンボ／チェイン倍率・OVERDRIVE 表示。

## 7. 検証計画

1. **ヘッドレスのシミュレーション**（TypeScript を esbuild で束ねて Node 実行）
   - CPU 同士の対戦を数十ラウンド回して、上下の有利不利・平均試合時間・技の使用率・中立ブロックの帰属ミスを測る
   - 仮想ネットワーク（遅延・ゆらぎ・ロスを注入）で巻き戻し量・相手の表示遅れ・帯域を測る
   - **技の成立率**を遅延ごとに測る（ラグ補償が効いているかの唯一の数値的な証拠）
2. **実ブラウザの自動操作**（Playwright、2タブ対戦まで）
   - キャンバスの画素からパドル位置を読み、**押した向きに動くか**を検証する
   - **押した方向の技が出るか**を検証する（上＝スマッシュ、下＝ボレー。参加側でも同じか）
3. **実機（iPhone Safari）で触る** — 表示崩れ・タッチ・音は実機でしか分からない

> **教訓：試合が成立することを確認しても、操作が正しいことの確認にはならない。** 参加側の上下左右が逆でも「試合は最後まで進み、勝敗は両者で一致する」ためテストは通ってしまう。
